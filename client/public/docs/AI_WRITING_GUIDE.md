# PlayBoard 文件編寫指南

用這份指南來指導其他 AI 編寫 PlayBoard 的使用文件。

## 寫作規則

### 必須遵守

1. **語言**：使用繁體中文，不使用簡體中文（禁用詞：「添加」→ 使用「新增」）
2. **簡潔**：面向一般使用者，不用技術術語
3. **No Emoji**：避免使用 emoji 符號
4. **實用**：重點放在「如何使用」而不是「如何設計」
5. **結構**：簡單清晰的標題和短句子

### 禁止

- 複雜的系統架構圖
- API 細節、技術棧、資料庫設計
- 開發者指南內容
- 過多的表格和超連結
- 冗長的解釋

## PlayBoard 核心功能簡述

### PlayBook（學習路徑）

- **定義**：分步驟的課程
- **包含**：內容、測驗、問卷、互動應用
- **追蹤**：自動記錄進度和時間
- **主題**：支援不同視覺風格（default、jungle、ocean）

### 內容管理

- **用途**：發佈文章、教材等
- **功能**：富文本編輯、標籤分類、預覽發佈

### 測驗

- **用途**：線上考試
- **題型**：單選、複選
- **功能**：自動評分、成績記錄

### 滿意度調查

- **用途**：收集回饋
- **題型**：滿意度評分（5 階）、開放式問題、選擇題
- **功能**：統計分析、資料匯出

### 客製化頁面

- **用途**：上傳互動應用（HTML/CSS/JS）
- **執行**：安全沙盒環境
- **觸發**：手動、計時、互動、完成等方式

## 使用者角色

### 管理員

- 建立編輯所有內容
- 查看統計報告
- 管理使用者

### 一般使用者

- 參與 PlayBook
- 閱讀內容
- 參加測驗和問卷

## 用途場景

- 課程教學
- 員工培訓
- 產品導覽
- 知識學習路徑
- 調查反饋

## Prompt 範本

### 寫新文件時使用這個 Prompt

```
我需要為 PlayBoard 教育平台寫一份使用指南。

系統背景：
- PlayBoard 是學習互動平台
- 有 5 大功能：PlayBook、內容、測驗、問卷、客製化頁面
- [根據需要補充特定功能的細節]

寫作要求：
1. 使用繁體中文（禁用簡體詞如「添加」，改用「新增」）
2. 面向一般使用者，不用技術術語
3. 不要使用 emoji
4. 避免複雜的架構、表格、超連結過多
5. 重點是「怎麼用」不是「怎麼設計」
6. 句子簡短清晰
7. 只包含實際有用的資訊

文件內容需求：
[填入具體需求，例如：]
- 說明 PlayBook 的基本概念
- 如何建立 PlayBook
- 不同步驟類型的用法
- 常見問題解答

文件格式：
- Markdown
- 用簡單的標題結構
- 列表用短句子
- 步驟用編號列表

文件位置：client/public/docs/users/[文件名].md
```

### 修改現有文件時使用這個 Prompt

```
我需要簡化 PlayBoard 的使用文件。

當前問題：
- 內容過於複雜/技術性
- emoji 太多
- 有不必要的架構圖表
- [具體問題]

修改要求：
1. 移除所有 emoji
2. 移除技術架構、API細節、資料庫設計等開發者內容
3. 簡化為面向一般使用者的內容
4. 保留實用的操作步驟
5. 按照「寫作規則」重新組織

目標：
- 讓一般使用者快速了解功能
- 簡短易讀（不超過 [頁數]）
```

## 需要編寫的文件清單

### 已完成

- `users/overview.md` - 系統總覽

### 需要編寫（建議順序）

1. `users/playbook-guide.md`

   - 什麼是 PlayBook
   - 如何參與 PlayBook
   - 進度記錄和時間追蹤
   - 完成後看什麼

2. `users/exam-guide.md`

   - 什麼是測驗
   - 如何參加測驗
   - 成績和反饋

3. `users/survey-guide.md`

   - 什麼是問卷
   - 如何填寫問卷
   - 問卷類型說明

4. `users/content-guide.md`

   - 瀏覽內容
   - 內容分類

5. `users/custom-page-guide.md`

   - 什麼是客製化頁面
   - 如何參與互動應用

6. `users/progress-tracking.md`

   - 查看個人進度
   - 理解統計數據

7. `faq.md`
   - 常見問題
   - 故障排除

## 品質檢查清單

編寫完後檢查：

- [ ] emoji 不要太多
- [ ] 沒有技術術語（架構、API、資料庫等）
- [ ] 沒有複雜的表格或圖表
- [ ] 句子簡短（10 字以內為佳）
- [ ] 有清晰的步驟說明
- [ ] 面向一般使用者可理解
- [ ] 使用繁體中文
- [ ] 超連結不超過 5 個

## 補充說明

### 需要提及的核心概念

**PlayBook**

- 一個完整的學習路徑
- 由多個步驟組成
- 步驟可以是內容、測驗、問卷、互動應用
- 依序完成

**進度**

- 系統自動追蹤
- 可以看到完成進度
- 記錄花費時間

**主題**

- 不同 PlayBook 可有不同視覺風格
- 不影響功能，只影響外觀

**問卷統計**

- 系統自動統計結果
- 可看平均分數、分布等

### 不需要提及

- 後端技術（Node.js、Express、MongoDB 等）
- 前端框架（Vue、Vite 等）
- 資料庫設計
- API 端點
- 系統架構圖
- 開發者指南
- 部署方式
