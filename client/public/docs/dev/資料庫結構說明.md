# PlayBoard 資料庫結構說明

## 概述

PlayBoard 使用 MongoDB 作為資料庫，透過 Mongoose ODM 進行資料建模和操作。本文件詳細說明系統中所有資料表（Collection）的結構、關聯關係，以及如何新增新的資料模型。

## 資料庫技術棧

- **資料庫**: MongoDB (NoSQL 文件導向資料庫)
- **ODM**: Mongoose 7.x
- **連線方式**: MongoDB Atlas / 本地 MongoDB
- **資料格式**: BSON (Binary JSON)

## 詳細資料表結構

### 1. User（使用者）

**用途**: 管理系統使用者，包含管理員和一般用戶。

**主要欄位**:

| 欄位      | 類型    | 說明                              |
| --------- | ------- | --------------------------------- |
| username  | String  | 用戶名（唯一，3-20 字元）         |
| password  | String  | 密碼（bcrypt 加密，查詢時不返回） |
| email     | String  | 電子郵件（唯一）                  |
| role      | String  | 角色（admin \| user）             |
| avatar    | String  | 頭像 URL                          |
| active    | Boolean | 是否啟用                          |
| createdAt | Date    | 建立時間                          |
| updatedAt | Date    | 更新時間                          |

**索引**:

- `username`: 唯一索引
- `email`: 唯一索引

**中間件**:

- 儲存前自動加密密碼（bcrypt）
- 更新時自動更新 `updatedAt`

### 2. PlayBook（學習路徑）

**用途**: 管理結構化的學習路徑，每個 PlayBook 包含多個步驟。

**主要欄位**:

| 欄位            | 類型     | 說明                                         |
| --------------- | -------- | -------------------------------------------- |
| title           | String   | 標題（最大 100 字元）                        |
| slug            | String   | URL 識別符（唯一）                           |
| description     | String   | 描述（最大 1000 字元）                       |
| steps           | Array    | 步驟陣列（PlayBookStep）                     |
| status          | String   | 狀態（draft \| published）                   |
| theme           | String   | 主題樣式（default \| jungle \| ocean）       |
| displayType     | String   | 展示模式（overview \| stepByStep）           |
| estimatedTime   | Number   | 預估時間（分鐘）                             |
| tags            | [String] | 標籤陣列                                     |
| category        | String   | 分類                                         |
| difficulty      | String   | 難度（beginner \| intermediate \| advanced） |
| viewCount       | Number   | 瀏覽次數                                     |
| completionCount | Number   | 完成次數                                     |
| publishedAt     | Date     | 發布時間                                     |
| createdBy       | ObjectId | 創建者（ref: User）                          |
| lastModifiedBy  | ObjectId | 最後修改者（ref: User）                      |

**子文件: PlayBookStep**:
| 欄位 | 類型 | 說明 |
|------|------|------|
| stepNumber | Number | 步驟編號 |
| type | String | 類型（content \| exam \| survey \| customPage） |
| resourceId | ObjectId | 資源 ID（動態引用） |
| title | String | 步驟標題 |
| description | String | 步驟描述 |
| isRequired | Boolean | 是否必須 |
| timeLimit | Number | 時間限制（分鐘） |

**索引**:

- `slug`: 唯一索引
- `status, publishedAt`: 複合索引

**中間件**:

- 自動生成 slug（使用 slugify）
- 發布時自動設置 `publishedAt`
- 步驟變更時自動計算 `estimatedTime`

### 3. PlayBookProgress（學習進度）

**用途**: 追蹤用戶在 PlayBook 中的學習進度。

**主要欄位**:

| 欄位           | 類型     | 說明                         |
| -------------- | -------- | ---------------------------- |
| playBook       | ObjectId | PlayBook ID（ref: PlayBook） |
| userId         | String   | 用戶 ID                      |
| userName       | String   | 用戶名稱                     |
| currentStep    | Number   | 當前步驟                     |
| completedSteps | [Number] | 已完成步驟陣列               |
| stepResults    | Map      | 步驟結果（Map 類型）         |
| totalSteps     | Number   | 總步驟數                     |
| startedAt      | Date     | 開始時間                     |
| lastActiveAt   | Date     | 最後活動時間                 |
| completedAt    | Date     | 完成時間                     |
| timeSpent      | Number   | 花費時間（秒）               |
| isCompleted    | Boolean  | 是否完成                     |
| completionRate | Number   | 完成率（%）                  |

**索引**:

- `playBook, userId`: 複合唯一索引
- `playBook, isCompleted`: 複合索引

**中間件**:

- 儲存時自動更新 `lastActiveAt`
- 自動計算 `completionRate`

## 新增資料模型步驟

### 步驟 1：建立模型檔案

在 `server/models/` 目錄下建立新的模型檔案。

**檔案命名規範**:

- 使用大駝峰命名法（PascalCase）
- 檔案名稱應為單數形式
- 範例：`Product.js`、`Order.js`

```bash
# 建立新檔案
touch server/models/Product.js
```

### 步驟 2：引入 Mongoose

在檔案開頭引入必要的套件：

```javascript
const mongoose = require("mongoose");
const Schema = mongoose.Schema;
```

### 步驟 3：定義 Schema

設計資料結構並定義 Schema：

```javascript
const ProductSchema = new Schema(
  {
    name: {
      type: String,
      required: [true, "產品名稱為必填"],
      trim: true,
      maxlength: [100, "產品名稱不能超過100個字元"],
    },
    price: {
      type: Number,
      required: [true, "價格為必填"],
      min: [0, "價格不能為負數"],
    },
    category: {
      type: String,
      enum: ["電子產品", "服飾", "食品", "其他"],
      default: "其他",
    },
    inStock: {
      type: Boolean,
      default: true,
    },
    createdBy: {
      type: Schema.Types.ObjectId,
      ref: "User",
      required: true,
    },
    createdAt: {
      type: Date,
      default: Date.now,
    },
    updatedAt: {
      type: Date,
      default: Date.now,
    },
  },
  {
    timestamps: true, // 自動管理 createdAt 和 updatedAt
  }
);
```

### 步驟 4：建立索引

為常用查詢欄位建立索引以提升效能：

```javascript
// 單一欄位索引
ProductSchema.index({ name: 1 });

// 複合索引
ProductSchema.index({ category: 1, createdAt: -1 });

// 唯一索引
ProductSchema.index({ sku: 1 }, { unique: true });
```

### 步驟 5：新增中間件（Middleware）

在資料操作前後執行自訂邏輯：

```javascript
// 儲存前中間件
ProductSchema.pre("save", function (next) {
  // 自動更新 updatedAt
  this.updatedAt = Date.now();

  // 其他邏輯...
  next();
});

// 刪除前中間件
ProductSchema.pre("remove", async function (next) {
  // 清理相關資料
  await RelatedModel.deleteMany({ product: this._id });
  next();
});
```

### 步驟 6：新增實例方法（Instance Methods）

為模型實例新增自訂方法：

```javascript
// 計算折扣價格
ProductSchema.methods.getDiscountedPrice = function (discountPercentage) {
  const discount = (this.price * discountPercentage) / 100;
  return this.price - discount;
};

// 檢查是否有庫存
ProductSchema.methods.checkStock = function () {
  return this.inStock && this.quantity > 0;
};
```

### 步驟 7：新增靜態方法（Static Methods）

為 Model 類別新增靜態方法：

```javascript
// 查找熱門產品
ProductSchema.statics.findPopular = function (limit = 10) {
  return this.find({ inStock: true }).sort({ viewCount: -1 }).limit(limit);
};

// 依分類統計
ProductSchema.statics.countByCategory = function () {
  return this.aggregate([{ $group: { _id: "$category", count: { $sum: 1 } } }]);
};
```

### 步驟 8：新增虛擬欄位（Virtual Fields）

建立不儲存在資料庫中的計算欄位：

```javascript
// 虛擬欄位：完整顯示名稱
ProductSchema.virtual("displayName").get(function () {
  return `${this.name} (${this.category})`;
});

// 設定 toJSON 時包含虛擬欄位
ProductSchema.set("toJSON", { virtuals: true });
```

### 步驟 9：建立並導出 Model

```javascript
const Product = mongoose.model("Product", ProductSchema);
module.exports = Product;
```

**注意事項**:

- Model 名稱使用單數形式
- Mongoose 會自動將 Collection 名稱轉為小寫複數形式
- 範例：`Product` → `products`

### 步驟 10：建立 Controller

在 `server/controllers/` 建立對應的 Controller：

```javascript
// server/controllers/productController.js
const Product = require("../models/Product");

// 獲取所有產品
exports.getAllProducts = async (req, res) => {
  try {
    const products = await Product.find()
      .populate("createdBy", "username email")
      .sort({ createdAt: -1 });

    res.status(200).json({
      success: true,
      data: products,
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      message: error.message,
    });
  }
};

// 建立產品
exports.createProduct = async (req, res) => {
  try {
    const product = await Product.create({
      ...req.body,
      createdBy: req.user._id,
    });

    res.status(201).json({
      success: true,
      data: product,
    });
  } catch (error) {
    res.status(400).json({
      success: false,
      message: error.message,
    });
  }
};

// 其他 CRUD 操作...
```

### 步驟 11：建立 Routes

在 `server/routes/` 建立路由檔案：

```javascript
// server/routes/productRoutes.js
const express = require("express");
const router = express.Router();
const { protect, authorize } = require("../middleware/auth");
const {
  getAllProducts,
  createProduct,
  getProduct,
  updateProduct,
  deleteProduct,
} = require("../controllers/productController");

// 公開路由
router.get("/", getAllProducts);
router.get("/:id", getProduct);

// 需要認證的路由
router.use(protect);
router.post("/", authorize("admin"), createProduct);
router.put("/:id", authorize("admin"), updateProduct);
router.delete("/:id", authorize("admin"), deleteProduct);

module.exports = router;
```

### 步驟 12：註冊路由

在 `server/server.js` 中註冊新的路由：

```javascript
// server/server.js
const productRoutes = require("./routes/productRoutes");

// ...其他程式碼...

app.use("/api/products", productRoutes);
```

### 步驟 13：建立前端 Service

在 `client/src/services/` 建立對應的前端服務：

```javascript
// client/src/services/product.service.js
import apiClient from "./api.service";

const ProductService = {
  // 獲取所有產品
  async getAllProducts(params = {}) {
    const response = await apiClient.get("/products", { params });
    return response.data;
  },

  // 獲取單一產品
  async getProduct(id) {
    const response = await apiClient.get(`/products/${id}`);
    return response.data;
  },

  // 建立產品
  async createProduct(data) {
    const response = await apiClient.post("/products", data);
    return response.data;
  },

  // 更新產品
  async updateProduct(id, data) {
    const response = await apiClient.put(`/products/${id}`, data);
    return response.data;
  },

  // 刪除產品
  async deleteProduct(id) {
    const response = await apiClient.delete(`/products/${id}`);
    return response.data;
  },
};

export default ProductService;
```

## Schema 欄位類型參考

### 基本類型

| 類型     | 說明           | 範例                          |
| -------- | -------------- | ----------------------------- |
| String   | 字串           | `type: String`                |
| Number   | 數字           | `type: Number`                |
| Date     | 日期時間       | `type: Date`                  |
| Boolean  | 布林值         | `type: Boolean`               |
| Buffer   | 二進制資料     | `type: Buffer`                |
| Mixed    | 任意類型       | `type: Schema.Types.Mixed`    |
| ObjectId | MongoDB ID     | `type: Schema.Types.ObjectId` |
| Array    | 陣列           | `type: [String]`              |
| Map      | 映射（鍵值對） | `type: Map`                   |

### 常用驗證器

| 驗證器                | 適用類型       | 說明               |
| --------------------- | -------------- | ------------------ |
| required              | All            | 必填欄位           |
| unique                | String, Number | 唯一值             |
| min / max             | Number, Date   | 最小/最大值        |
| minlength / maxlength | String, Array  | 最小/最大長度      |
| enum                  | String, Number | 允許的列舉值       |
| match                 | String         | 正則表達式驗證     |
| validate              | All            | 自訂驗證函數       |
| default               | All            | 預設值             |
| trim                  | String         | 去除前後空白       |
| lowercase / uppercase | String         | 轉換大小寫         |
| select                | All            | 查詢時是否預設返回 |
| ref                   | ObjectId       | 關聯其他 Model     |

## 最佳實踐

### 1. 命名規範

- **Model 名稱**: 使用單數形式的大駝峰命名法（PascalCase）

  - 正確：`User`, `PlayBook`, `Question`
  - 錯誤：`Users`, `playbook`, `question`

- **欄位名稱**: 使用小駝峰命名法（camelCase）

  - 正確：`userName`, `createdAt`, `isPublic`
  - 錯誤：`user_name`, `CreateAt`, `is-public`

- **Collection 名稱**: MongoDB 會自動轉換為小寫複數形式
  - `User` → `users`
  - `PlayBook` → `playbooks`
  - `Question` → `questions`

### 2. 索引設計

- 為常用查詢欄位建立索引
- 複合索引的欄位順序很重要
- 避免過多索引（影響寫入效能）
- 唯一索引確保資料不重複

```javascript
// 單一索引
Schema.index({ field: 1 }); // 1 = 升序, -1 = 降序

// 複合索引
Schema.index({ field1: 1, field2: -1 });

// 唯一索引
Schema.index({ field: 1 }, { unique: true });

// 稀疏索引（允許 null 值）
Schema.index({ field: 1 }, { sparse: true });
```

### 3. 時間戳管理

使用 Mongoose 內建的 `timestamps` 選項：

```javascript
const Schema = new mongoose.Schema(
  {
    // 欄位定義...
  },
  {
    timestamps: true, // 自動新增 createdAt 和 updatedAt
  }
);
```

### 4. 資料驗證

- 在 Schema 層級進行資料驗證
- 使用有意義的錯誤訊息
- 考慮前端和後端雙重驗證

```javascript
{
  email: {
    type: String,
    required: [true, '電子郵件為必填'],
    match: [/^\S+@\S+\.\S+$/, '請輸入有效的電子郵件地址']
  }
}
```

### 5. 關聯資料處理

使用 `ref` 和 `populate` 處理關聯資料：

```javascript
// Schema 定義
{
  author: {
    type: Schema.Types.ObjectId,
    ref: 'User'
  }
}

// 查詢時填充關聯資料
Model.find().populate('author', 'username email');
```

### 6. 虛擬欄位

使用虛擬欄位進行計算，避免冗餘資料：

```javascript
Schema.virtual("fullName").get(function () {
  return `${this.firstName} ${this.lastName}`;
});

// 設定 toJSON 時包含虛擬欄位
Schema.set("toJSON", { virtuals: true });
Schema.set("toObject", { virtuals: true });
```

### 7. 錯誤處理

統一處理 Mongoose 錯誤：

```javascript
try {
  await Model.create(data);
} catch (error) {
  if (error.name === "ValidationError") {
    // 驗證錯誤
    const errors = Object.values(error.errors).map((err) => err.message);
  } else if (error.code === 11000) {
    // 唯一索引衝突
    const field = Object.keys(error.keyPattern)[0];
  }
}
```

## 常見問題

### Q1: 如何處理大量資料查詢？

使用分頁和查詢優化：

```javascript
const page = parseInt(req.query.page) || 1;
const limit = parseInt(req.query.limit) || 10;
const skip = (page - 1) * limit;

const data = await Model.find().limit(limit).skip(skip).sort({ createdAt: -1 });

const total = await Model.countDocuments();
```

### Q2: 如何實現軟刪除？

新增 `deletedAt` 欄位和中間件：

```javascript
const Schema = new mongoose.Schema({
  // ...其他欄位
  deletedAt: {
    type: Date,
    default: null,
  },
});

// 軟刪除方法
Schema.methods.softDelete = function () {
  this.deletedAt = new Date();
  return this.save();
};

// 查詢時排除已刪除資料
Schema.pre(/^find/, function (next) {
  this.where({ deletedAt: null });
  next();
});
```

### Q3: 如何處理檔案上傳？

使用 `multer` 處理檔案上傳，將檔案路徑儲存在資料庫：

```javascript
{
  coverImage: {
    filename: String,
    originalName: String,
    url: String,
    size: Number,
    mimeType: String
  }
}
```

### Q4: 如何實現全文搜尋？

建立文字索引：

```javascript
Schema.index({
  title: "text",
  content: "text",
});

// 搜尋
Model.find({ $text: { $search: "關鍵字" } });
```
